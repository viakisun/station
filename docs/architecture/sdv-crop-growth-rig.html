Jetson 일체형 PoC가 아니라, 산업용 분산 노드 SDV를 생육분석 로봇에 적용한 레퍼런스

각 기능을 MCU · VPU · LPU · ACU · Telemetry · HMI · Local Agent로 물리/논리 분리하고, 모든 노드를 표준 Signal / Command / Event 계약으로 통합한다. 본 문서 = 1차 산출물(HW·SW·디스플레이·통신·안전권한· 데이터흐름 설계 = "온로봇 SDV 개발 벤치" 합의용). 2차 = 이 설계 기준 기본 베이스 프로그램(real 코드 + mock 데이터).

✕ Jetson 한 대에 카메라·모터·UI·AI·LTE 다 연결 ✓ 노드 분리 + Local Agent 통합 게이트웨이 표준계약 = 이음새mock → 실제 보드 스왑

01 System Overview

온로봇(edge)과 클라우드를 분리. 로봇의 두뇌·안전은 로봇 위, 클라우드는 함대 감독만. Local Agent가 노드를 잇는 통합 게이트웨이.

그림 1 — 시스템 토폴로지. 노드는 분리되어 Local Agent로 모이고, Telemetry만 클라우드로 다리를 놓는다.

02 Node Architecture — 책임 · I/O · 금지

책임·표준 I/O(신호/명령)·금지사항을 못박아 구현 단계에서 역할이 섞이지 않게 한다.

Emergency cutoff domain

14 로봇 동작 워크플로우 (Run Loop)

로봇이 실제로 움직이고 생육분석을 수행하는 런타임 절차. ①–④ 준비 → ⑤–⑧ waypoint 반복 루프 → ⑨ 업링크. 모든 명령은 Local Agent 권한 게이트를 통과하고, 물리 안전(E-stop)이 최상위다.

물리 분리 단계: Phase A(리그: MCU 물리분리·Agent 별도 RPi·VPU/ACU 프로세스분리) → Phase B(프로토타입: VPU/ACU 물리분리·LPU 추가) → Phase C(제품: Control/HMI/Cloud 망 분리·Telemetry Gateway·OTA 정식화). 물리 분리는 단계적, 논리/계약/권한 분리는 처음부터 필수.

이 설계가 증명하는 8가지 (산업용 아키텍처 부합)

✓ Jetson 일체형 구조가 아니다
✓ 안전·실시간 제어가 분리되어 있다(MCU/HW)
✓ AI(VPU)와 자율(ACU)이 분리되어 있다
✓ HMI가 하드웨어를 직접 제어하지 않는다
✓ Cloud가 내부 제어망에 직접 접근하지 않는다
✓ 모든 노드가 표준 계약으로 연결된다
✓ mock 노드를 실제 하드웨어로 교체할 수 있다
✓ 장애/Health/ACK/Policy가 구조에 포함된다
