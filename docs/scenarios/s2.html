S2 · 사무실/개발실
이기종 펌웨어 통합 검증·배포
행위자 배포 관리자산출물 JJ-U03이 모듈은 6종 계약 중 Firmware Manifest 게이트

메타파머스·에이지로보틱스·대동로보틱스·KIRO·농업과학원 — 서로 다른 제조사 모듈의 펌웨어를 한 도구로 안전하게 검증·배포한다. 정적분석 → 호환성 매트릭스 → 릴리즈 승인(게이트) → OTA 배포 → 실패 시 롤백까지, 이기종 펌웨어가 잘못된 조합으로 현장에 나가지 않도록 단계마다 자동 게이트가 작동한다. 모든 펌웨어는 module_id 스파인에 묶인 Firmware Manifest 계약으로 등록된다.

1
펌웨어 등록 — Manifest·checksum
제조사 펌웨어 바이너리를 version·checksum·compatibility_rules를 담은 Firmware Manifest로 등록한다. checksum으로 무결성을, manifest로 어떤 모듈·버전을 위한 펌웨어인지를 명시해 레지스트리에 귀속시킨다.
모듈 펌웨어→Firmware Manifest→레지스트리
화면: 펌웨어 등록 마법사
2
정적분석 결과 확인
등록된 펌웨어에 자동 정적분석이 실행되어 critical/major/minor finding을 분류한다. critical finding이 남아 있으면 릴리즈 승인 게이트(G2)에서 그대로 차단 사유가 되며, 화면은 사유와 해결행동을 함께 제시한다.
펌웨어 바이너리→Static Analysis→finding 등급
화면: 정적분석 결과
3
호환성 매트릭스 확인
이 펌웨어가 어느 로봇 / 모듈 / HMI / Telemetry 조합에 배포 가능한지를 호환성 규칙으로 자동 매핑한다. compatible/incompatible를 신호등으로 보여 주어, 잘못된 조합에 펌웨어가 흘러가는 것을 사전에 막는다.
펌웨어→호환성 규칙→대상 조합(로봇·모듈·HMI·Telemetry)
화면: 호환성 매트릭스
4
릴리즈 승인 (G2)
정적분석·호환성·Audit 세 조건이 모두 통과해야 릴리즈가 승인된다. 하나라도 미충족이면 승인이 막히고, 화면은 어떤 조건이 왜 막혔는지(사유)와 무엇을 해야 하는지(해결행동)를 함께 안내한다.
정적분석·호환·Audit→G2 릴리즈 승인→배포 가능 릴리즈
화면: 릴리즈 승인 — pass
5
OTA 배포 계획 수립
승인된 릴리즈로 OTA 배포 계획을 세운다 — canary 비율·롤아웃 단계·롤백 조건(G6/G7)을 정의해 소수 대상부터 점진 배포하고, 이상 지표 시 자동 롤백되도록 안전망을 건다.
승인 릴리즈→OTA Plan (canary·rollback)→대상 플릿
화면: OTA 배포 계획
6
OTA 진행 모니터
배포가 시작되면 대상별 단계(다운로드·검증·적용·재기동)를 실시간 추적한다. 각 대상의 성공/실패와 진행률을 한 화면에서 보며, 롤백 조건에 걸리는 대상이 있는지 감시한다.
OTA Plan→진행 모니터→대상별 단계 상태
화면: OTA 진행 모니터
7
실패 시 롤백
롤백 조건을 만족하면 해당 대상을 이전 안정 버전으로 되돌리고, 누가·언제·왜 롤백했는지 감사 기록을 남긴다. 이기종 펌웨어라도 동일한 안전망·추적성으로 운영을 보호한다.
이상 감지(G6/G7)→Rollback→이전 안정 버전·감사 기록
화면: 롤백
G2 BLOCKED 배포 계획 생성 차단
G2 — 정적분석 critical 2건 미해결 + Audit 미승인: 릴리즈 승인 두 조건이 동시에 미충족이라 OTA 배포 계획 생성 자체가 차단된다. 검증되지 않은 펌웨어가 이기종 플릿에 배포되는 것을 시스템이 원천 차단한다.
해결: 정적분석 상세로 진입해 critical finding을 수정하거나 근거와 함께 waiver(예외 승인)를 요청하고, 누락된 Audit Package를 승인받는다 → 두 조건 충족 시 G2 재승인·배포 계획 생성.
