S8 · 사무실
버전 업그레이드 — 호환성 게이트·canary·롤백
행위자 배포관리자·운영자버전 skew를 게이트가 자동 차단

기존 모듈의 펌웨어/Capability 버전 업(예: FW-CAM-2.4.1 → 2.4.2)을 현장 깨짐 없이 안전하게 적용하는 상황이다 — 운영 중 버전 갱신 역시 매우 흔한 일이다. 문제는 새 버전이 일부 조합과만 호환되거나, map/parameter 버전이 어긋난 채 배포되면 현장에서 통합이 깨진다는 것. STATION은 버전 불일치(skew)를 게이트가 배포 전 자동 차단하고, 정적분석 → 호환성 게이트 → canary 배포 → OTA 모니터 → 실패 시 자동 롤백까지 안전망을 단계마다 건다.

CORE 핵심
버전 skew(map·parameter·펌웨어)를 VersionCompatibility 게이트가 배포 전 자동 차단 — 현장에서 깨지는 통합 사고를 사전에 방지한다. "이런 경우(버전 업)가 많다"를 "손쉽게(게이트가 알아서 차단)"로 증명하는 확장성·안전망 패턴이다.
1
새 버전 등록·정적분석
신규 펌웨어 FW-CAM-2.4.2를 version·checksum·compatibility_rules를 담은 Firmware Manifest로 등록하면 자동 정적분석이 실행된다. critical/major/minor finding이 분류되고, 동시에 이 버전이 갱신하는 호환성 규칙이 레지스트리에 반영된다.
새 펌웨어 버전→Firmware Manifest→호환성 규칙 갱신
화면: 펌웨어 등록 마법사 · 새 버전
2
호환성 게이트 (VersionCompat)
새 버전이 어느 로봇/모듈/HMI 조합에 영향을 주는지 VersionCompatibility 게이트가 자동 판정한다 — 호환되는 조합은 통과, map/parameter가 어긋난 조합은 warn 또는 blocked로 신호등에 뜬다. 어긋난 채 배포되는 일을 게이트가 사전에 막는다.
새 버전→VersionCompat 게이트→영향 조합(warn/blocked)
화면: 호환성 매트릭스
3
배포 계획 — canary
게이트를 통과한 영향 조합 중에서 canary 그룹부터 점진 배포하도록 OTA 계획을 세운다 — canary 비율·롤아웃 단계·롤백 조건을 정의해, 전 플릿 일괄 대신 소수 대상에서 먼저 새 버전을 검증한다.
통과 조합→OTA Plan (canary)→canary 그룹 우선
화면: OTA 배포 계획
4
OTA 진행 모니터
배포가 시작되면 대상별 단계(다운로드·검증·적용·재기동)를 실시간 추적하고, 실패하는 대상을 즉시 감지한다. 각 대상의 성공/실패·진행률을 한 화면에서 보며 롤백 조건에 걸리는 대상을 감시한다.
canary 배포→진행 모니터→대상별 단계·실패 감지
화면: OTA 진행 모니터
5
실패 시 자동 롤백
canary에서 롤백 조건을 만족하면 해당 대상을 이전 안정 버전으로 자동 복구하고, 누가·언제·왜 롤백했는지 감사 기록을 남긴다. 새 버전이 현장 전체로 번지기 전에 차단되어, 버전 업이 운영을 깨지 않는다.
canary 이상 감지→Rollback→이전 안정 버전·감사 기록
화면: 롤백
BLOCKED VersionCompatibility — 버전 불일치
VersionCompatibility — map_version / parameter_version 불일치 대상이 존재한다: 새 펌웨어와 맵·파라미터 버전이 어긋난 조합이 있어, 해당 대상으로의 배포가 차단(또는 confirm)된다. 어긋난 버전 조합이 현장에 나가 통합이 깨지는 사고를 게이트가 원천 차단한다.
해결: 불일치 대상의 맵/파라미터를 새 버전에 맞춰 동기화한 뒤 호환성 게이트를 재평가한다 → 전 대상 버전이 정합되면 배포 차단이 풀려 재배포.
→ 운영으로: S4 통합 관제
