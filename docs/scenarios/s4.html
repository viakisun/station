S4 · 관제실
이기종 다중 로봇 통합 관제 ★핵심
행위자 비아 운영자 이기종 N대 → 한 화면

메타·에이지·대동·KIRO·농과원의 서로 다른 산출물로 조립된 로봇들을 — 비아 운영자가 한 화면에서 하나처럼 관제한다. 이기종 N대가 각기 다른 벤더 모듈로 구성됐어도, 6종 표준 계약으로 매칭돼 통합 대시보드·맵·작업계획이 동일하게 작동한다. 이 시나리오가 STATION이 "잇는" 일을 가장 직접적으로 보여주는 핵심 장면이다.

1
현장 로봇 Device Registry 페어링·등록
현장에 투입된 이기종 로봇을 Device Registry에 페어링·등록하고, 어느 벤더 모듈로 구성됐는지(조합)를 확정한다. 이후 모든 관제·작업은 이 조합 정의를 따른다.
이기종 로봇→ module_id / robot_id 스파인→ Device Registry
⛁ Control · Device Registry
2
텔레메트리 게이트웨이 데이터 인입 확인
등록된 로봇·센서의 데이터가 게이트웨이를 통해 표준 채널로 흘러들어오는지 확인한다. 벤더가 달라도 같은 채널 스키마로 들어와야 한 화면 통합이 가능하다.
로봇·센서 데이터→ Telemetry Channel(게이트웨이)→ 표준 채널 인입
⌁ Control · 텔레메트리 인입
3
통합 대시보드 — 다중 로봇을 한 화면
메타 매니퓰 + 에이지 모바일 + 대동 측위 + 엔드이펙터로 구성된 다중 로봇의 KPI·상태를 한 화면에 통합한다. 이기종이라는 사실이 운영자에게는 보이지 않는다 — 그것이 통합관제의 핵심.
이기종 로봇들→ 전 계약 매칭→ 통합 관제 한 화면
▦ Control · 통합 대시보드 (JJ-U01)
4
작업 계획·로봇 배정
작업을 계획하고 적합한 로봇을 배정한다. STATION이 추천을 제시하고, 배정 전 게이트(경로검증·펌웨어 버전·캘리브레이션·장애 freeze)를 통과해야만 확정된다.
작업 계획→ 추천 + 게이트(경로·버전·캘리브·장애)→ 로봇 배정
▤ Control · 작업 계획 (JJ-U01)
5
실시간 맵·다중 로봇 협업 스케줄
배정된 로봇들의 위치·작업을 실시간 맵에서 보며, 다중 로봇이 충돌 없이 협업하도록 스케줄을 조율한다. 측위(대동)가 달라도 표준 좌표로 한 맵에 모인다.
⌖ Control · 실시간 맵·협업 스케줄
6
현장으로 작업 전송 — Context 핸드오프
확정된 작업을 현장 태블릿으로 전송한다. ctx 쿼리로 robot_id·work_session_id를 운반해, 관제실과 현장이 같은 세션 컨텍스트를 공유한다(끊김 없는 핸드오프).
작업→ ctx 핸드오프 (robot_id·work_session_id)→ 현장 태블릿
⇄ Control · Context 핸드오프 → 현장
BLOCKED G1 / G7 — 배정 불가
G1 미검증 경로이거나, G7 대상 로봇에 open critical incident가 있으면 — 작업 배정이 차단된다. 미검증·장애 중 로봇으로는 작업을 내보낼 수 없다.
해결: 경로를 재검증하거나(G1), 장애 상세로 이동해 incident를 처리·해제(G7)한 뒤 배정을 재시도한다.
→ 작업이 현장으로 전송됨 — S5 · 조합 로봇 현장 운용으로 이어진다.
