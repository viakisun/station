S6 · 현장·관제
이기종 가로지르는 문제 추적·개선
행위자 오퍼레이터·유지보수·관제 어느 모듈 문제든 한 시스템에서

어느 기관 모듈에서 문제가 나도 — work_session_id·module_id 스파인 덕에 한 시스템에서 원인까지 추적·조치하고, 필요 시 펌웨어 개선으로 연결(폐루프)한다. 메타·에이지·대동·KIRO/농과원 어느 벤더의 모듈이 원인이어도, 이벤트→장애→원인→조치→Close가 같은 흐름으로 흐른다.

1
작업 중 이상 이벤트
작업 중 이상이 감지된다 — 비전 프레임드롭(KIRO 엔드이펙터) 또는 관절 과열(메타 매니퓰). 이벤트는 스파인에 묶여 관제 이벤트 스트림으로 흐른다.
모듈 이상→ Event 스파인 (work_session_id)→ 관제 이벤트 스트림
⚠ Ops · 장애 운영 대시보드 (JJ-U02)
2
Event → Incident 승격
critical 이벤트가 장애(Incident)로 승격된다. 승격된 장애는 G7 게이트와 연동돼, 해당 로봇·모듈로의 신규 작업 배정을 freeze한다.
critical 이벤트→ 승격 + G7 freeze→ Incident
⛗ Ops · Event → Incident 승격
3
원인 분류 · 영향 범위
어느 module_id·firmware_id가 원인인지 taxonomy tree로 추적하고, 같은 모듈을 쓰는 다른 로봇까지 영향 범위를 산정한다.
이벤트→ 원인 taxonomy (module_id·firmware_id)→ 원인 모듈·펌웨어
⌥ Ops · 원인 분류·영향 범위
4
조치 가이드 / 현장 캘리브
분류된 원인에 맞는 표준 조치를 수행한다. 현장에서 처리 가능한 경우 캘리브레이션을 재수행하고, 모듈 교체·점검이 필요하면 유지보수로 연결한다.
원인 모듈→ 표준 조치 가이드→ 현장 캘리브·유지보수
⛏ Field · 조치 가이드 / 현장 캘리브
5
긴급정지 상황
e-stop이 발동하면 전체화면이 잠긴다. 현장 오퍼레이터는 해제 불가(하드 거부) — 해제하려면 현장 관리자 인증이 필요하다. 권한이 없는 사용자에게는 해제 동작 자체가 보이지 않는다.
e-stop→ 권한·복구 체크리스트→ 관리자 해제
⛔ Field · 긴급정지 (e-stop 잠금)
6
재발 확인 · Close
조치 후 재발 여부를 확인하고 장애를 닫는다. 재발/waiver 게이트를 통과해야 closed 상태가 되며, 필요 시 펌웨어 개선으로 연결(→ S2 루프)해 폐루프를 완성한다.
조치 완료→ 재발/waiver 게이트→ closed → 펌웨어 개선 루프
⛒ Ops · 장애 Close (재발/waiver 게이트)
BLOCKED 권한 하드 거부 — e-stop 해제 불가
현장 오퍼레이터의 e-stop 해제는 시각·동작 모두 차단된다. 해제 버튼이 보이지 않고, 시도해도 동작하지 않는다(하드 거부).
해결: 현장 관리자 권한 인증 + 복구 체크리스트 완료 후에만 해제할 수 있다.
→ 개선 루프: S2 펌웨어 개선 / S1 재온보딩
